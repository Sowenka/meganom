### 1. Задеплоить PHP из `_api/` (фиксация согласия по 152-ФЗ)

Код готов и проверен `php -l`, но на сервер не залит. Фронт уже отправляет
`consent_given` и `consent_version`, старый бэкенд их молча игнорирует, поэтому
сайт работает, но факт согласия нигде не сохраняется.

Что мешает залить вслепую (см. `memory/deploy-notes.md`):

- Все файлы в `_api/` имеют UTF-8 BOM. BOM ломает API: `headers already sent`
  и битый JSON. BOM надо срезать перед заливкой.
- Локальный `config.php` опережает серверный: включает IP-whitelist админки
  (`ADMIN_IPS` + `require_admin_ip()`). Заливка без сверки может закрыть `/admin`,
  если текущего IP админа нет в списке. Новые функции согласия (`consent_record`,
  `client_ip`, `consent_email_block`) лежат именно в `config.php`, поэтому залить
  остальное без него нельзя: будет fatal error.
- Папка на сервере называется `api/`, локально `_api/`.
- `migrate.php` на сервер НЕ деплоится.

Порядок: скачать серверный `config.php`, построчно сверить, показать список IP
в whitelist, срезать BOM, залить, проверить `/admin` и API.

Затронутые файлы: `_api/config.php`, `_api/contact.php`, `_api/subscribe.php`,
`_api/auth/register.php`, `_api/bookings/create.php`.

### 10. Предсуществующие ошибки eslint

`npm run lint` даёт 3 ошибки, не связанные с текущими правками:

- `src/pages/Home.jsx:26` (`useCountUp`) и ещё два места: setState внутри
  эффекта, "cascading renders".
- `src/components/WeatherWidget.jsx`: `const Icon = getWeatherIcon(...)` в теле
  рендера, "Cannot create components during render".

Плюс около 258 предупреждений `no-unused-vars` на импортах, которые реально
используются в JSX: конфиг eslint не видит JSX-использования. Стоит починить
конфиг, иначе предупреждения бесполезны как сигнал.
